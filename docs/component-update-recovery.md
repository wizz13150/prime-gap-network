# Interrupted Windows updates

Updates are optional. A prepared component selection is authenticated before
Horizon drains its owned workers and Core. Code is installed in immutable
cohorts; wallets, chain databases and scientific results keep their folders.

An unresolved transaction blocks another installation. The Software updates
window offers **Restore previous version**. Recovery verifies both complete
code inventories, the original network/genesis and the exact owned process
identities. It restores only the recorded bounded application profiles, never
wallet or chain files. A reused process ID is not ownership.

Recovery is offline: it does not depend on downloading another release. The
previous cohort is selected only after its native UI and configured Core
confirm startup health. Repeating a completed recovery does not restart it
again. Unverifiable or foreign state is retained for diagnosis rather than
overwritten or forcibly terminated.

Qualification includes a real Windows interruption after the verified graceful
shutdown of UI/Core and before profile rebinding. Recovery preserved the same
wallet, chain tip, balances, three device cards and disabled mining settings.
This is evidence for that interruption boundary, not certification of every
possible power-loss boundary or an external public HTTPS update deployment.

Unchanged files can share backing storage between verified immutable cohorts
inside the installation store. An unpacked application or staging cache is
always copied independently. Unsupported hardlinks fall back to a fully
admitted independent copy. Complete inventories are verified either way.
The store charges shared file identities once, up to 1 GiB of unique file
content and 16,384 directory entries. It retains previous versions; reaching
the budget refuses further allocation without deleting active or old code.
